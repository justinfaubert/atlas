Bits per verse

The same Bible in 56 languages, measured by how many bits it takes to write each verse down instead of how many letters or words. Lengths differ fourfold. Information differs by a few percent.

1. Length varies fourfold, information barely moves

Each dot is one language, placed by how far it sits from the median. Characters and words scatter widely; compressed bits pull in tight. The orange dots are abjads (scripts that leave out vowels), which drop 10–20% of the bits because readers supply the vowels themselves.

2. The cooling curve

A character model that looks back 0, 1, 2… 6 characters. With no context, languages look very different (spread 17.6%). Given about five characters, they settle onto nearly the same rate (7.2%). The thick line is the median.

3. Word order and word forms trade off

Shuffling the words inside each verse costs extra bits: that extra is what word order carries. Languages that pack meaning into word forms (Finnish, Latin) carry little in order; languages built from separate words (Thai, Japanese) carry a lot. The total stays put: 6.6% spread with order, 14.5% without. This reproduces Koplenig et al. (2017), our first check against a published law.

4. Every language agrees on where information is dense

Bits per character, chapter by chapter, after removing each language's own level. The profile is the same across languages (two random halves agree at 0.98). Peaks are genealogies and name lists and the Song of Songs. Dips are passages that repeat another book: Chronicles copying Kings, Isaiah 36–39, Jeremiah 52, and in the New Testament, Mark and the passages it shares with Matthew and Luke. A plain compressor finds the synoptic parallels in every language.

5. What this says about the Atlas results

The chapters the embedding runs found hard to translate are not the ones where languages package information differently (partial Spearman −0.03). They are the ones whose content is surprising in every language (+0.22, CI 0.17 to 0.28, length controlled; +0.18 with source names controlled too). That matches the layer picture: content matters, language barely does.

6. Digging deeper: is it a law?

Three checks, run after the first result.

A stronger estimator does not erase the 7%

If the spread came from a weak model, a stronger one should shrink it. It doesn't. PPMd, the strongest compressor here, finds 10% fewer bits than the character model (207 vs 230 bits per verse) but the same spread. Giving it more text shrinks the spread only slowly, by about a quarter of a point per doubling. So about 7% looks like real variation between these translations, not just estimator noise.

Inside a verse, information is spread evenly, except at the end

In every language, the first half of a verse carries 48–52% of its bits (median 49.8%). That's what uniform information density predicts. The one systematic difference is the last fifth of the verse. In verb-first and verb-middle languages it's the heaviest part, because new objects and names come last. In verb-final languages it's light, because the closing verb ending is predictable (Japanese is the extreme). The difference between the groups is 0.075 (permutation p = 0.0002).

Spoken aloud, time follows length, not bits

The CMU Wilderness dataset lists how many hours of New Testament audio were aligned in about 700 languages. I matched 31 well-aligned recordings to our texts. Reading time tracks the number of characters (r = 0.84). Once length is accounted for, it doesn't track bits at all (partial r = 0.09). Readers keep a steadier rate in characters per second (spread 14%) than in bits per second (21%). So in these recordings the conservation is in the message, not in the speaking rate. This is a rough first look: the recordings use other translations, and aligned hours depend on how much of each recording aligned.

Caveats

These are bits of written text, so orthography moves them (vowels, tone marks). Word entropy depends on how words are split (the Chinese, Japanese, Thai and Vietnamese files are pre-tokenised). An order-6 character model is a ceiling, not the true rate; the test is the spread, not the level. Code: experiments/information/ in the Atlas repo.
